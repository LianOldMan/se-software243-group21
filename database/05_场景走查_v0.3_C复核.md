## 3. 已核对通过的业务点

- **S1 正常预留**：先检查可售，再建立有效订单并把书置为“已预留”；`availability_status` 与有效订单同事务维护。
- **S2 取消后再预留 + 旧请求重放**：取消旧订单后书恢复可售，新订单可建立；旧订单请求只能命中旧订单，不得释放新订单或把书改回可售。
- **S3-A 同书竞争**：两人几乎同时预留同书，最终至多一条有效订单；失败方不获知成功方身份/订单详情。
- **S3-B-1 同书同 token 幂等**：同一买家、同一 token 重试不产生第二条有效订单；返回已有订单或可核对提示。
- **S3-B-2 跨书 token 复用拒绝**：同一 token 用于另一本书时拒绝，不能借 token 绕开唯一约束。
- **S4 自购拒绝**：按 R-04 拒绝，不产生订单，不改变书状态。
- **S5 越权取消**：非订单买家不能取消；拒绝后订单、书籍、历史均不变。
- **S6 价格边界**：0、-5、12.345 拒绝；12.34 接受；不自动四舍五入。
- **S7 同一订单并发取消**：至多一次取消生效，订单只转为已取消一次，书籍只释放一次，不出现半完成状态；`AC-05-5` 在共享需求 v0.5.6 中存在，引用有效。
- **A-1～A-8 断言**与上述场景一致；责任划分表、5.1 跨表状态说明没有发现逻辑冲突。
- **证据边界**：全文保持“静态设计推演、未执行 SQL、未实测”的口径，没有把断言写成已通过。
