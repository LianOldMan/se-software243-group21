## 二、概念—逻辑—关系图检查结果

1. **实体**：`USER` → `user_account`、`BOOK_LISTING` → `book_listing`、`RESERVATION_ORDER` → `reservation_order`。原概念编号 `book_id` 映射 SQL `listing_id`，订单 `created_at` 对应 `placed_at`；字段映射在概念说明与字典中留有理由。
2. **主键与外键**：`user_account.user_id`、`book_listing.listing_id`、`reservation_order.order_id` 为单列主键；`book_listing.seller_id`、`reservation_order.buyer_id`、`reservation_order.listing_id` 为三处非空外键；图中父端 1、子端 0..N，满足“无订单书籍/用户可以存在，订单必须指向买家和书籍”。
3. **历史与条件唯一**：一个 listing 可以引用多条**历史**订单，而状态“有效”同时 ≤1；订单生成列 `active_listing_id = CASE WHEN order_status='有效' THEN listing_id ELSE NULL END` 搭配 UNIQUE 保护写入侧。不能将这一约束误画为书与全部订单 1:1。
4. **幂等**：`request_token CHAR(36) NOT NULL` 与 `UNIQUE(buyer_id,request_token)` 在字典、关系图、走查相符；UUID 签发/客户端同动作复用/跨书拒绝属于**未来服务端实现**，数据库 CHAR 不能自行执行 UUID 语义校验。
5. **取消时间**：`cancelled_at` 与 `order_status` 的空值配对 CHECK 及 `cancelled_at>=placed_at` 有字典/SQL 约束依据；A 按 B 最新 P1 让走查 r2 采用 DB `NOW(6)`，并统一会话 UTC 作为运行条件，避免两套时钟。脚本的 SET time_zone 只改脚本连接，**不是已部署的业务连接配置**。
6. **书籍状态**：`book_listing.availability_status` 是受控冗余，不能凭单表 CHECK 自动达到“已预留 ⇔ 恰一条有效订单”，必须同事务更新且只在**事务提交后的稳定状态**核对 A-1/A-2。
7. **价格与规范化**：`price DECIMAL(10,2)`、`CHECK(price>0)` 与业务要求“最多两位小数”不等价；非法 `12.345` 必须按输入原字符串拒绝。三张表均用单列主键，生成列是行内技术派生，跨表受控冗余具有写入异常风险并明确维护责任。

**总体静态结论**：概念 ER v0.4、字典 v0.3、独立关系图 v0.3 与走查 v0.3-r2 的**主实体/主外键/基数/主要约束在设计层面一致**。这不表示实现已运行或不同 SQL 方言全部兼容。
