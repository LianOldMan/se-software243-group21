## 2. A 的字段映射和三张表核对

| 概念层 | 逻辑层实际名称 | 核对结论 |
|---|---|---|
| USER：用户编号、预置账号标识 | `user_account.user_id` PK、`account_code` NOT NULL UNIQUE | 一类用户同时可作买家/卖家，不引入注册、密码字段 |
| BOOK_LISTING：`book_id` | `book_listing.listing_id` PK | 一条发布记录对应一本实物书；同名不同书无需强制唯一 |
| BOOK_LISTING：发布者联系 | `book_listing.seller_id → user_account.user_id` NOT NULL FK | 父端 1、子端 0..N |
| BOOK_LISTING：书名、作者、价格、成色、选填说明 | `title`、`author`、`price`、`condition_grade`、`description` | 四项必填、成色三档、说明可空；输入价格最多两位小数须由应用拒绝无效精度 |
| BOOK_LISTING：`status`、`created_at` | `availability_status`、`published_at` | 可售/已预留；系统生成发布时间，列表倒序 |
| RESERVATION_ORDER：订单标识、买家、书籍 | `order_id` PK、`buyer_id` FK、`listing_id` FK | 三个 FK 中订单两条均非空；一书可有多条**历史**订单 |
| RESERVATION_ORDER：`status`、`created_at`、`cancelled_at` | `order_status`、`placed_at`、`cancelled_at` | 有效/已取消；下单时间必填；取消后时间非空且不早于下单 |
| 实验二技术设计 | `request_token CHAR(36) NOT NULL`、`active_listing_id` 生成列 + UNIQUE | 幂等与“同书至多一条有效订单”的参考实现；**不是实验一新增业务功能** |

三条真实外键均为 `NOT NULL`，父端 1、子端 0..N；`book_listing → reservation_order` 是**0..N 历史订单**，同时有效 ≤1 由条件 UNIQUE 另行保证，不得画成 1:1。原来的 `condition`、`created_at` 等概念名和 SQL 列名是有记录的**层次转换**，不是矛盾。

## 3. A 的需求—模型—业务场景一致性核对

| 实验一确认范围 | 模型/设计对应 | 核对结果及限制 |
|---|---|---|
| FR-01/02、UC-01 发布、校验字段 | `book_listing` 四项必填 + `published_at`；价格正数、成色 CHECK | 对应；**R-03 超两位小数不可只靠 DECIMAL** |
| FR-03/04、UC-02/03 检索、列表/详情与可售状态 | `title`、`author`、`availability_status`、`published_at`、`description` | 对应；检索词只是请求条件，**不新建搜索表** |
| FR-05/06、UC-04 预留、并发、禁止自购 | 订单表两条 FK、条件生成列 UNIQUE、`request_token`、S1/S3 | 对应设计预期；自购检查、重复 token 语义及两表更新需服务/事务实现 |
| FR-07/08、UC-05 取消、保留历史、旧单不得释放新单 | `order_id` 定位、`order_status`、`cancelled_at`、S2 | 对应；取消须验证实际买家、当前有效状态与事务顺序 |
| NFR-01/02/03 | 设计提供约束和未来核查入口 | **均未执行性能/可靠性/易用性测试，不能写达标** |

**跨表不变量**：对事务提交后的稳定状态，“书籍已预留 ⇔ 该书恰有一条有效订单”。`UNIQUE(active_listing_id)` 仅保证**最多一条**，`availability_status` 只是便于读取的受控冗余字段，跨表等价关系仍要靠事务维护并通过断言核对。

**仍未决（不得擅自通过）**：B-Q-04 匿名检索、B-Q-11 异常数据修复政策、B-Q-12 同书重复发布判重、C-Q-12 预置账号数量。
