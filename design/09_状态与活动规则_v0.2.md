## 0. 目的与边界

本文件把 `ReservationOrder` 的合法状态迁移、UC-04 下单活动的正常/异常路径、状态与活动之间的对应关系写成可检查的文字，供 A/B 走查和后续详细设计引用。

- 只使用统一约定 v0.3 已确认的 `OrderStatus={有效, 已取消}`、`ListingStatus={可售, 已预留}`，不新增“已支付/已完成/已发货/已逾期”等状态。
- 只描述业务状态和类职责，不设计数据库表结构、不写 SQL、不引入支付/退款/物流。
- 图中的“设计推演”不是运行结果；本文件不把任何预期写成“已通过测试”。
- 失败、拒绝、重复请求都不是新状态；它们返回错误码，已有订单和书籍状态保持不变。

## 1. 状态机

### 1.1 状态集合

| 状态 | 类型 | 含义 | 是否持久化 |
|---|---|---|---|
| 初始（Initial） | 伪状态 | 买家尚未成功创建订单 | 否 |
| 有效（Active） | 业务状态 | 订单占用一本实物书，书籍为“已预留” | 是，`order_status='有效'` |
| 已取消（Cancelled） | 业务状态/业务终态 | 订单已失效，历史保留，书籍可恢复“可售” | 是，`order_status='已取消'` |
| 终止（Final） | 终止伪状态 | 订单生命周期结束，记录归档保留 | 否 |

`已取消` 是业务终态：旧订单不能复活；再次预留必须创建新的 `orderId`，不能把旧订单改回“有效”。

### 1.2 合法迁移

| 编号 | 起点 | 事件 | 守卫条件 | 动作 | 终点 |
|---|---|---|---|---|---|
| T-01 | 初始 | `ReservationService.placeReservation`（由 `ReservationController.reserveBook` 调用） | 账号有效；书存在且可售；买家不是发布者；`requestToken` 合法且未跨书复用；锁后复查仍可预留 | 创建 `ReservationOrder`，`orderStatus=有效`，`placedAt=DB NOW`；书籍 `availabilityStatus=已预留`；提交事务 | 有效 |
| T-02 | 有效 | `cancelReservation` / `cancelIfActive(...) = 1 行 → ReservationOrder.markCancelled(dbNow)` | 操作者 `buyerId == order.buyerId`；订单当前为“有效”；按 `orderId` 定位，不按 `listingId` 猜 | `orderStatus=已取消`，`cancelledAt=DB NOW`，`activeListingId=NULL`；无其他有效订单时书籍恢复“可售”；提交事务 | 已取消 |
| T-03 | 已取消 | —（生命周期结束） | 订单已取消 | `«lifecycle»` 记录归档/保留，不改变业务状态 | 终止 |

> 说明：T-03 是生命周期结束，不是业务上的“完成交易”。本实验没有交易完成、支付、物流，不能把终止写成“已完成”。

### 1.3 状态不变量

| 编号 | 不变量 | 检查方式 |
|---|---|---|
| I-01 | 同一本书同一时刻至多一条有效订单 | `activeListingId` 生成列 + UNIQUE；服务层锁后复查 |
| I-02 | 有效订单的 `cancelledAt` 必须为 `NULL`；已取消订单的 `cancelledAt` 必须非空 | 应用校验 + `CHECK(cancelled_at >= placed_at)` |
| I-03 | 已取消订单的 `activeListingId` 必须为 `NULL` | 生成列定义 |
| I-04 | 取消只改变指定 `orderId` 的订单及其关联书籍，不删除历史、不批量取消 | 按 `orderId` 条件更新；检查其他订单 |
| I-05 | 旧订单 O1 取消后，新订单 O2 是另一条记录；O1 的旧请求不能改 O2 或再次释放书籍 | 状态条件 + 订单标识；旧请求返回 `ORDER_NOT_ACTIVE` |
| I-06 | 失败/拒绝不留下半完成数据 | 事务回滚；失败后复查订单数、书籍状态、历史记录 |

### 1.4 拒绝与失败（不产生状态迁移）

| 事件 | 触发条件 | 结果 | 状态变化 |
|---|---|---|---|
| 非订单买家取消 | `buyerId != order.buyerId` | `FORBIDDEN_CANCEL` | 无 |
| 重复取消 | 订单已是“已取消” | `ORDER_NOT_ACTIVE` | 无 |
| 旧订单取消请求再次到达 | 旧订单 O1 已取消，O2 已存在 | `ORDER_NOT_ACTIVE`；只按 O1 定位，不能触碰 O2 | 无 |
| 订单不存在 | `orderId` 无记录 | `ORDER_NOT_FOUND` | 无 |
| 账号/token 不合法 | 账号无效或 token 格式错误 | `INVALID_USER` / `INVALID_TOKEN` | 无 |
| token 跨书复用 | 同买家同 token 已绑定另一本书 | `TOKEN_TARGET_MISMATCH` | 无 |
| 自购 | `buyerId == listing.sellerId` | `SELF_RESERVATION` | 无 |
| 书不可售/已被预留 | 锁后复查不通过 | `LISTING_NOT_FOUND` / `ALREADY_RESERVED` | 无 |
| 并发冲突 | 唯一约束或锁后复查失败 | `ALREADY_RESERVED` / 冲突错误 | 事务回滚，无半完成数据 |

这些分支在图中用红色异常出口或黄色注释表示，不画成新的订单状态。

## 2. 下单活动

### 2.1 参与对象

| 对象 | 职责 |
|---|---|
| 买家 | 发起预留，提供 `listingId` 与 `requestToken` |
| `ReservationController` | 接收请求、做参数格式校验、调用服务、把业务错误映射为响应；不承担事务和跨表状态判断 |
| `ReservationService` | 事务边界；账号/token 校验；幂等查询；锁书；自购检查；锁后复查；创建订单；更新书籍状态；提交/回滚 |
| `ReservationOrderRepository` | 按买家+token 查询、按书统计有效订单、插入订单、条件取消 |
| `UserAccountRepository` | 按买家 ID 读取并核对预置账号 |
| `BookListingRepository` | 按 `listingId` 锁定/读取书籍，更新可用状态 |
| `ReservationOrder` | 订单实体；`markCancelled(dbNow)` 只允许有效订单取消 |
| `BookListing` | 书籍实体；`availabilityStatus` 是受控冗余，由服务在同一事务维护 |

### 2.2 正常路径

| 步骤 | 参与者/对象 | 动作 | 结果 |
|---|---|---|---|
| A1 | 买家 → Controller | 提交 `reserveBook(buyerId, listingId, requestToken)` | 请求进入系统 |
| A2 | Controller → UserAccountRepository | `users.findById(buyerId)` 核对账号；校验必填、token 格式 | 账号或 token 不合法则 `INVALID_USER` / `INVALID_TOKEN`，结束 |
| A3 | Service → OrderRepository | 按 `buyerId + requestToken` 查询 | 命中同书：返回原订单，`replayed=true`；命中跨书：`TOKEN_TARGET_MISMATCH`；未命中继续 |
| A4 | Service | 开启事务；`lockById(listingId)` | 锁定书籍，进入事务 |
| A5 | Service | 检查书存在且可售；检查买家不是发布者 | 不满足则对应异常，回滚 |
| A6 | Service | 锁后复查 token：命中同书返回原单、命中跨书拒绝；未命中才 `countActiveByListing(listingId)` | 已有有效订单则 `ALREADY_RESERVED`；否则继续 |
| A7 | Service | `insert(order)`；`updateAvailability(已预留)`；`commit` | 返回 `RESERVED`，活动结束 |

### 2.3 异常出口

| 编号 | 触发点 | 错误码 | 回滚/后置保证 |
|---|---|---|---|
| E1 | 账号或 token 格式 | `INVALID_USER` / `INVALID_TOKEN` | 不写库；不产生订单 |
| E2 | 同 token 已绑另一本书 | `TOKEN_TARGET_MISMATCH` | 不把 A 书订单当成 B 书成功；不新增订单 |
| E3 | 书不存在/不可售 | `LISTING_NOT_FOUND` / `ALREADY_RESERVED` | 回滚；书籍状态不被错误占用 |
| E4 | 买家是发布者 | `SELF_RESERVATION` | 回滚；不产生订单 |
| E5 | 已有有效订单 | `ALREADY_RESERVED` | 回滚；不产生第二条有效订单 |
| E6 | 并发冲突/系统故障 | 冲突错误/系统错误 | 事务回滚；失败后无半完成数据 |

### 2.4 token 与幂等约定

- `requestToken` 是服务端在首次下单请求前签发的 36 字符 UUID；同一逻辑请求的重试必须复用，新动作生成新值。
- `UNIQUE(buyer_id, request_token)` 防止同一逻辑请求重复建单；唯一冲突时服务读取原订单并比较 `listingId`：
  - 同买家、同书、同 token：返回原订单当前状态，`replayed=true`；
  - 同买家、不同书、同 token：拒绝 `TOKEN_TARGET_MISMATCH`；
  - 不能把 A 书的订单当作 B 书下单成功。
- 锁后复查 token，避免“查询时未命中、写入时已被另一请求占用”的竞态。

### 2.5 事务与并发

- 事务从 `lockById(listingId)` 开始，到订单插入和书籍状态更新后提交；任一步失败回滚。
- 同一逻辑动作的网络重试、死锁或暂时性故障重试必须复用原 token，不得自动换新 token；只有用户明确发起新动作才签发新 token。唯一冲突先回滚，再在新事务/新读取上下文查询：同书返回原单当前状态，跨书拒绝，未命中且同书已有有效单返回 `ALREADY_RESERVED`。
- `activeListingId` 生成列 + UNIQUE 是“同书至多一条有效订单”的数据库兜底；服务层锁后复查是业务兜底。
- 书籍状态 `availabilityStatus` 是受控冗余，不是第二个事实源；它必须与订单状态在同一事务中更新。
- 并发下单时，锁粒度为书籍记录；未获得锁的请求等待或失败，不能绕过锁直接写入。
- 并发取消同一订单时，条件更新（`WHERE order_status='有效' AND buyer_id=?`）只允许一个请求成功，其余返回 `ORDER_NOT_ACTIVE`。

## 3. 六个走查场景映射

> 场景编号沿用小组走查习惯；A/B 的最终场景表如使用不同编号，以文字对应关系为准，不硬改对方编号。

| 场景 | 给定 | 操作 | 预期 | 关联迁移/活动 |
|---|---|---|---|---|
| S1 正常预留 | 书可售，买家非卖家，token 新 | 提交预留 | 新订单有效；书“已预留”；返回订单标识 | T-01；A1-A7 |
| S2 取消后再预留 + 旧请求重放 | O1 有效；O2 可创建；旧 O1 取消请求稍后到达 | 取消 O1，创建 O2，重放 O1 取消 | O1 已取消且历史保留；O2 有效；旧请求 `ORDER_NOT_ACTIVE`，不影响 O2 | T-02；异常表“旧订单取消请求” |
| S3 同书竞争 | 书可售；两个买家几乎同时提交 | 两个请求竞争 | 至多一个有效订单；失败方 `ALREADY_RESERVED`；书最终“已预留” | T-01；I-01；锁 + UNIQUE |
| S4 自购 | 买家就是发布者 | 提交预留 | `SELF_RESERVATION`；不产生订单 | 异常 E4 |
| S5 越权取消 | O1 属于 U2；U3 尝试取消 | U3 用 O1 的 orderId 取消 | `FORBIDDEN_CANCEL`；O1、书、历史均不变 | T-02 守卫失败 |
| S6 重复/并发取消 | O1 有效；同一买家重复或并发取消 | 两次取消 | 一次成功；其余 `ORDER_NOT_ACTIVE`；不重复释放、不删除历史 | T-02；条件更新 |

## 4. A 类职责核对（交叉检查）

以 `design/01_统一类与操作约定_v0.3.md` 为准，检查 A 的类职责是否足以支撑下单、取消、错误处理和事务。以下是 C 的核对清单，不擅自修改 A 的类图。

| 检查点 | A 类职责是否支持 | 说明/建议 |
|---|---|---|
| 请求参数校验与错误映射 | 支持 | `ReservationController` 负责格式/必填；业务错误由 Service 返回，Controller 不吞错 |
| 下单事务边界 | 支持 | `ReservationService.placeReservation` 应开启事务，锁书、复查、插入、更新书籍、提交；Controller 不管理事务 |
| 取消的身份与状态守卫 | 支持 | 只有订单买家本人；按 `orderId` 定位；`cancelIfActive(orderId,buyerId,dbNow): Int` 返回影响行数，恰好 1 行才成功 |
| 取消的实体动作 | 支持 | `ReservationOrder.markCancelled(dbNow): void` 只允许有效订单；已取消抛 `ORDER_NOT_ACTIVE`，不返回 false、不覆盖旧 `cancelledAt`，实体不执行 SQL |
| 同书至多一条有效订单 | 支持 | `activeListingId` 生成列 + UNIQUE 兜底；Service 锁后 `countActiveByListing` 复查 |
| 书籍状态一致性 | 支持，需强调 | `availabilityStatus` 是受控冗余；下单/取消同一事务更新；提交后校验“可售 ⇔ 无有效订单”“已预留 ⇔ 恰一条有效订单” |
| token 幂等/跨书拒绝 | 支持 | Repository 按 `buyerId+token` 查询；唯一约束兜底；唯一冲突后读原订单比较 `listingId` |
| 旧请求不影响新订单 | 支持 | 旧 O1 已取消，条件更新失败；不能按 `listingId` 批量取消，不能触碰 O2 |
| 自购检查 | 支持 | 跨表比较 `buyerId` 与 `listing.sellerId`；数据库 FK 不能表达，必须服务层检查 |
| 失败回滚 | 支持 | 任一异常回滚；不得留下“订单已建、书未预留”或反向的半完成状态 |

**结论**：A 的类职责覆盖下单、取消、错误处理和事务；A v0.3 §4.2 已明确 `ReservationService` 事务边界、`markCancelled` 的 `ORDER_NOT_ACTIVE` 拒绝语义、`cancelIfActive` 的 `Int` 影响行数，C 已复核通过。本表作为交叉检查记录保留。
