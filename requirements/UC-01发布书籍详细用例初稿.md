# UC-01 发布书籍｜详细用例初稿 v0.1

> 软件243班第21组 · 软件工程导论实验一 · 组长 A 负责。**本稿待组内人工评审，不是已经通过的最终用例或测试结果。**

## 1. 基本信息

| 字段 | 内容 |
| --- | --- |
| 用例编号 | UC-01 |
| 用例名称 | 发布书籍 |
| 目标 | 卖家提供一本闲置书籍的必要信息，系统确认输入有效后创建对应的发布记录，以便其他用户检索、查看和预留。 |
| 主要参与者 | 卖家（使用预置测试账号） |
| 触发条件 | 卖家发起“发布书籍”操作。 |
| 前置条件 | 当前操作者使用系统提供的预置测试账号，能够提交待发布的书籍信息。 |
| 成功后置条件 | 新增且只新增一条与本次提交相符的书籍发布记录，代表一本实物书；其初始状态为“可售”；系统反馈发布成功及记录标识。 |
| 失败后保证 | 不新增书籍发布记录；已存在的书籍记录不改变；系统清楚指出失败原因，保留无需重填的已输入信息（保留输入为小组建议，待确认）。 |
| 关联需求 | FR-01、FR-02；B-01、B-03；S-01；R-01、R-03（后两项仍为小组候选规则）。 |
| 相关用例 | UC-02 检索书籍、UC-03 查看书籍（发布成功的记录可被后续使用；不表示 include/extend 关系）。 |
| 规则状态 | R-01“书名、作者、价格、成色必填”，R-03“价格大于 0”目前为组长初步同意，待全组三人确认。 |

## 2. 正常流程

1. 卖家发起发布书籍操作。
2. 系统提供发布信息的填写入口，提示需要填写的字段（当前候选：书名、作者、价格、成色）。
3. 卖家填写一本实物书籍的信息并提交。
4. 系统校验必填字段与价格规则；若不满足，转异常流 A1～A3。
5. 校验通过后，系统创建一条新的发布记录，并将该记录状态设为“可售”。
6. 系统向卖家反馈发布成功，并显示书籍名称、发布记录标识及当前状态。
7. 用例结束。

## 3. 异常或备选流程

| 编号 | 触发条件 | 系统反馈 | 对数据的保证 |
| --- | --- | --- | --- |
| A1 | 书名、作者、价格或成色任一必填项未填写（R-01 暂定） | 拒绝发布，指出缺少哪一项，允许卖家修正后重新提交。 | 无新增记录，原有记录不变。 |
| A2 | 价格为 0 或负数（R-03 暂定） | 拒绝发布，提示价格必须大于 0。 | 无新增记录，原有记录不变。 |
| A3 | 价格不是可用数值（例如仅填写非数字字符） | 拒绝发布，提示价格格式错误；价格的小数位与上限另待确认。 | 无新增记录，原有记录不变。 |
| A4 | 提交时暂时无法完成发布（系统故障，作为候选异常） | 显示“发布未完成，请稍后重试”类提示；不能把失败反馈成成功。 | 不产生半完成的可见发布记录。 |

## 4. 验收条件（拟定，未实测）

| 编号 | 给定条件 | 执行操作 | 预期结果 |
| --- | --- | --- | --- |
| AC-01-1 | 卖家账号可用，准备好一条书名、作者、价格、成色均有效的虚构教材数据。 | 提交发布。 | 恰好新增 1 条发布记录；字段与输入一致；初始状态“可售”；反馈成功。 |
| AC-01-2 | 其余字段均有效，书名留空。 | 提交发布。 | 拒绝并指出书名缺失；不新增记录。其他必填字段分别留空时同样成立。 |
| AC-01-3 | 其他字段有效。 | 分别将价格填为 0、-5 并提交。 | 均拒绝，提示价格规则；不新增记录。 |
| AC-01-4 | 其他字段有效。 | 将价格填为非数字文本后提交。 | 拒绝并说明价格格式不正确；不新增记录。 |
| AC-01-5 | 系统已有若干发布记录。 | 提交一条合法新记录并随后检索该书。 | 原有记录不变；新记录存在且状态“可售”；可被 UC-02 找到（检索匹配规则按最终确认版本）。 |

## 5. 需要小组确认

- R-01、R-03 是否由全组最终采纳；如修改，需同步 FR-01/02 与本用例。
- 成色采用自由文本还是固定选项？若固定选项，允许哪些值？
- 价格是否最多两位小数、有无上限、是否允许赠书（0 元）？
- 发布成功是否要展示发布记录标识？失败后是否保留已填写内容？
- 是否允许额外填写出版社、备注等非必填字段？本阶段不强制增加。
